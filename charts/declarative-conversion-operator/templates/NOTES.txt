{{- if not (.Capabilities.APIVersions.Has "cert-manager.io/v1") }}

⚠️  cert-manager.io/v1 was not detected in this cluster's API. Both this
    operator's own admission webhook and every ConversionWebhookServer
    instance's conversion webhook depend on cert-manager to issue their TLS
    certificates. Install cert-manager first
    (https://cert-manager.io/docs/installation/) — this chart does not
    vendor it. See the install matrix:
    https://terasky-oss.github.io/declarative-conversion-operator/installation/#cert-manager-install-matrix
{{- end }}

1. Wait for the manager and the default ConversionWebhookServer to become Ready:

     kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "declarative-conversion-operator.fullname" . }}-manager
{{- if .Values.conversionWebhookServer.create }}
     kubectl wait --for=condition=Available conversionwebhookserver/{{ .Values.conversionWebhookServer.name }} --timeout=180s
     kubectl get conversionwebhookserver {{ .Values.conversionWebhookServer.name }} -o wide
{{- else }}

     (conversionWebhookServer.create is false — create a ConversionWebhookServer
      CR yourself before applying conversion configs.)
{{- end }}

2. Prove a mapping offline with `convctl` (same engine the webhook uses)
   before it touches the cluster. From a clone of the repository:

     go run ./cmd/convctl test --xrd my-xrd.yaml --config my-xrdconversionconfig.yaml --samples ./samples/

   Full command reference:
   https://terasky-oss.github.io/declarative-conversion-operator/cli/

3. Apply your first conversion config. Copy a gallery example, or use the
   kitchen-sink fixture (every built-in strategy in one XRDConversionConfig):

     https://terasky-oss.github.io/declarative-conversion-operator/examples/
     https://terasky-oss.github.io/declarative-conversion-operator/examples/kitchen-sink/

     kubectl apply -f my-xrdconversionconfig.yaml
     kubectl get xrdconversionconfig my-config -o yaml

   status.conditions and status.spokeStatuses explain a stall. Common causes:
   Validated=False (a lossy field needs acknowledgeLossy: true), or
   WebhookServerReady=False (the ConversionWebhookServer is not Available yet).
