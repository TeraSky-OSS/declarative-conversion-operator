1. Wait for the default ConversionWebhookServer instance to become Ready:

     kubectl wait --for=condition=Available conversionwebhookserver/{{ .Values.conversionWebhookServer.name }} --timeout=120s
     kubectl get conversionwebhookserver {{ .Values.conversionWebhookServer.name }} -o wide

2. Create your first XRDConversionConfig, pointing spec.targetXRD.name at an
   existing Crossplane CompositeResourceDefinition with more than one
   version. See config/samples/terasky_v1alpha1_xrdconversionconfig.yaml in
   the repository for a starting example, and check its status once applied:

     kubectl apply -f my-xrdconversionconfig.yaml
     kubectl get xrdconversionconfig my-config -o yaml

   The `status.conditions` and `status.spokeStatuses` fields explain exactly
   what's blocking it if it isn't reaching phase=Applied — most commonly
   Validated=False (a lossy field needs `acknowledgeLossy: true`), or
   WebhookServerReady=False (the ConversionWebhookServer instance isn't
   Available yet).

3. Test conversions offline before applying, using the xrdconvctl CLI:

     xrdconvctl test --xrd my-xrd.yaml --config my-xrdconversionconfig.yaml --samples ./samples/
